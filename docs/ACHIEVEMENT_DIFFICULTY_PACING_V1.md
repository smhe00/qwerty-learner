# 成就系统：稀缺性与发放节奏 V1

## 目标与边界

- 面向初中生的长期 Learn 习惯，不把「按一次按钮」「打开一个章节」视为可反复炫耀的成就。
- **自然日最多解锁 1 枚新的永久成就**，因此任何连续自然日窗口内的每日平均新解锁数最多为 1（只统计新成就，不统计复习/活动提示）。
- 不修改 FSRS、答题判定、Learn 每日目标，也不调整用户已获得的成就记录。
- 真正达标但遇到当天名额已用尽的成就，完整证据入 V4 achievementEvents 的唯一待发队列；**不丢失、不重复、不回放历史造奖**。后续真实 Learn 事件到来时自动发放 1 枚。
- 稀有度越高优先发放；同稀有度按达到条件时间与成就 ID 排序。隐藏成就仍在解锁前保密。
- 真实成就可以在完成动作后的第二个自然日才揭晓，因此获奖的触发时间（firstTriggerEventId）和实际解锁时间（unlockedAt）分开保留。

## 首批 P0 门槛校准

| 成就 | 旧触发条件 | 新触发条件 |
| --- | --- | --- |
| 独立开篇（原「初次破译」） | 首个独立成功词 | 不同单词中，独立拼写正确累计至少 **16 个** |
| 自胜 | 连续 10 词无提示 | 至少两个学习日，连续 **64 词**无提示独立成功 |
| 渐入佳境 | 12 词内后半段提升 20pp | 至少 32 词，后半段提升 **40pp** |
| 拾遗成章（原「失而复得」） | 找回 1 个曾失败的词 | 独立找回 **6 个不同**的曾失败单词 |
| 扳回一局 | 曾失败 3 次的单词恢复 | 曾失败 **5 次**的同词恢复 |
| 毫厘得正 | 解决 1 个重复错误位置 | 独立解决 **2 个**重复错误位置 |
| 听声成词 | 纯听音独立正确 10 次 | 纯听音独立正确 **48 次** |
| 五日笃行（原「今日笃行」） | 完成 1 次推荐 Learn 目标 | **5 个不同日**完成推荐 Learn 目标 |
| 再启三程（原「再启一程」） | 达标后继续一次 | **3 个不同日**明确达标后继续，并开始真实后续学习 |
| 三境开拓（原「新境初开」） | 进入第 1 个单元 | 进入同一词库 **3 个不同单元** |

其余涉及 7/30/90 天延迟回忆、百词长期掌握、7/10 天坚持、隐藏逆转的 P0 条件本来较难，暂时保留，不以盲目加高所有指标的方式破坏可达性。

## 风险防线

1. **同词刷次数**：16 词初级奖按字典和词的唯一组合去重；恢复奖也必须是 6 个不同词；Typing/辅助提示/训练事件不计入独立正确。
2. **重复事件**：事件 ID 去重；奖项状态表仍以 achievementId 为唯一主键；待发队列在同一 Dexie 写事务内更新。
3. **数据安全**：不新增数据库表、不改变 V4 格式；待发内容是现有 achievementEvents 行上的可选 JSON 数组，V4 原样导出/导入。
4. **账号隔离**：继续使用 S1 独立工作区，同一个账号的奖章状态和待发资格同时随 V4 工作区迁移。
5. **日界线**：使用客户端当前本地自然日；多时区设备或设备时钟被人为修改时，需要专项实网验证，当前不能声称服务器级绝对发奖限额。
6. **不强迫学习**：仅在下一个自然日真实学习事件到来时领取待发奖；不因为空打开网页或后台闹钟强制发奖。

## 验证入口

- `tests/achievement/rarity-calibration.test.ts`：不同词、不同失败词、不同单元、不同学习日、去除 Typing 污染。
- `tests/achievement/award-pacing.test.ts`：同日多奖优先级、保存未发、跨天出队、重复/已解锁剔除、21 日内 19 枚奖项模型验证。
- `.github/workflows/achievement-gate.yml`：新测试必须参与 CI，且配合全站构建、现有领域模型与校验器。

**验收结论应来自 CI 真实执行日志。** 线上用户群体的实际每日解锁分布仍需匿名聚合数据或合成用户轨迹仿真，不把 1 人的模拟样本伪称为生产统计。
