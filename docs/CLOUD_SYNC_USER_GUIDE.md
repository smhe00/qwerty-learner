# QWERTY Plus Beta · 云账号与同步

> 2026-10-25 核对，已验收发布基线 `ea4ede53`。当前完整备份为 gzip `qwerty-backup-v4`；旧 V1/V3 操作说明不是当前指南。

## 本地优先与身份隔离

浏览器 IndexedDB 是日常学习工作区。未登录也能学习；匿名空间与各账号本地空间隔离。已有账号登录不得把匿名记录自动混入；新注册时可以按明确选择复制匿名记录。

完整 V4 包含六张业务表：`wordRecords`、`chapterRecords`、`reviewRecords`、`reviewWordStates`、`achievementEvents`、`achievementStates`，以及每日学习会话、个人设置和导航状态。它不只是当前词库或当天练习。

## 换设备：仍然保留单一有效登录

另一设备登录同一账号后，旧会话可能失效。这与本地记录的归属不同：认证失效不意味着旧设备的学习记录应被删除或改归匿名。

恢复联网后，在需要时重新认证同一账号；系统对受支持的同账号数据执行检查与自动协调。**单一登录不等于不支持多设备轮换，自动融合也不等于无限设备永久同时有效登录。**

## 同步结果应该怎样理解

| 情况 | 当前行为边界 |
| --- | --- |
| 两端一致 | 可成为无需完整传输的 no-op。 |
| 一方变化 | 按身份、基线和完整性检查决定上传或拉取。 |
| 同账号出现受支持的分叉 | 可以自动构造合并候选、校验并经安全事务恢复；不是必然要求用户二选一。 |
| 身份、结构或证据不满足安全条件 | 保留数据并阻止危险操作，不能静默强行覆盖。 |
| 请求超时或 HTTP 500 | 提交结果可能不确定；错误本身不能证明云端没有保存。 |

自动合并不是把所有字段简单相加。学习历史、引用、记忆状态、每日计划和个人设置有各自规则；设置与导航发生并行变化时，也不承诺保留每台设备的不同选择。工程语义见 [当前架构](./CLOUD_SYNC_ARCHITECTURE.md)。

## 自动流程与手动入口

登录/普通启动会检查完整 V4 历史。学习事件通过后台路径持久化和发送；恢复联网、页面可见及适用空闲时机可驱动相应恢复流程。完整快照恢复在受保护的事务边界执行，不是在用户输入时随意替换已挂载数据库。

每日全部完成仍可自动同步；“每个 Block 完成后自动同步”默认关闭，按本机当前账号保存。开启后按完成页反馈继续或处理失败，不影响离线记录首先保留在本机。

桌面使用账号入口和数据设置，手机使用“账号与云同步”：

- **立即同步**：进入受保护的同步流程。
- **刷新云端状态（只读）**：读取元信息，不上传、不恢复，不等于已同步。
- **下载云端备份**：保存云端完整备份。
- **处理同步冲突**：仅供自动处理未能完成时的高级核对与恢复，不是日常多端切换的必经步骤。

事件上传有回执，不等于完整六表和所有运行状态已经收敛；登录成功也不是同步成功。离线或认证无效时，不应承诺云端马上获得最新记录。

## 手动导入不等于自动合并

导出完整备份和校验文件不替换数据。导入则会**替换当前接收工作区**，需要明确确认；跨账号要核对接收身份，匿名接收值为 `LOCAL-ANONYMOUS`。

导入前必须保存当前备份。导入不是直接云覆盖授权；原同步基线失效后，下一次同步仍需重新核对，不能盲目使用旧 revision。

## 异常与恢复

先保留本机数据；必要时导出本地完整备份，并下载云端备份。认证过期时重新认证同一账号。不要清空浏览器或连点覆盖来“修复”同步。

只有确需高级恢复时，才在安全页面核对身份、版本及备份，并明确选择替换方向。保留本地可能覆盖云版本，保留云端可能替换本机，二者都不能当作无损合并。

本次发布首轮曾出现注册 HTTP 500、预期 revision 2 却读到 1；同源新测试身份复验通过，尚不能据此认定根因消除。首次失败注册中一个测试账号的创建/清理结果仍未确认；见 [已知风险](./release/BETA_CLOSEOUT_2026-10-25.md)。

## 站点与隐私

生产统一使用 `https://q.smhe.cn`，测试使用 `https://t.smhe.cn`。二者云存储隔离；GitHub Pages 云功能禁用。不要把 HTTP/HTTPS、默认域名/正式域名的浏览器存储当成同一份。

云备份不是客户端端到端加密。备份和诊断文件可能含学习数据；密码、令牌和文件不得公开。删除账号不等于所有离线设备本地副本同时消失。圈子实验 API 的账号删除保护应单独核验，不能为绕过限制而关闭保护。
