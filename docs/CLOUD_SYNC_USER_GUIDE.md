# QWERTY Plus Beta · 云账号与同步

> 当前云备份格式：`qwerty-backup-v4`（gzip）。本文面向 `0.2.0-beta.1` 用户；旧 V1/V3 云同步操作说明已过时，**请勿按历史文档手动上传/下载覆盖数据**。

## 1. 本地数据与云端数据

QWERTY Plus 是 **local-first** 学习工具：本机浏览器的 IndexedDB 是日常学习工作区；没有登录也可以正常学习。本机匿名工作区和每个云账号的本机工作区相互隔离。

登录云账号后，统一的“同步”功能负责检查和协调当前账号的本地备份与云端备份。一个完整 V4 备份包含学习记录、记忆状态、学习会话、成就及个人设置，不仅仅是当前选中的词库。

## 2. 如何同步

打开右上角账号入口登录，再到设置中的数据相关页面进行同步：

- **本地与云端一致**：无需重新上传。
- **仅本地更新**：安全检查通过后可上传。
- **仅云端更新**：安全检查通过后可拉取。
- **两边都有不同数据**：显示冲突，不会悄悄选择一端覆盖另一端。
- **账号与当前本机工作区不匹配、云端格式不受支持或远端状态无法验证**：阻止普通写入。

云同步采用 revision、内容指纹和 SHA 检查，不能简单地把“服务器返回错误”等同于“服务器肯定没保存”。**发生超时、HTTP 500、503 或提交状态不确定时，请先重新查看云端状态，再决定是否重试。**

## 3. 自动同步

学习数据首先持久化在当前本机工作区。每日学习会话完成后，登录账号可触发自动同步。

“每个 Block 完成后自动同步”是一个可选开关，**默认关闭**。开启后，Block 完成页会展示同步状态，并在安全同步结束后允许继续或退出；关闭后不影响本地数据保存。

## 4. 手动备份、恢复和跨账号

设置中的“导出完整备份”保存标准 gzip V4 文件。操作前建议下载并验证备份。

导入备份意味着**替换当前接收工作区的数据**，而非追加、合并，也不会自动覆盖云端。若来源身份不同，系统要求明确确认接收工作区 ID；本机匿名工作区的确认值为 `LOCAL-ANONYMOUS`，它不是云账号密码。

跨账号导入后，原同步基线将失效。目标账号如果已有不同的云备份，普通同步应显示冲突，而不是立即覆盖云端。

## 5. 发生冲突怎么办

1. 首先**下载本地完整备份和云端原始备份**，保留两个文件。
2. 在“处理同步冲突”中验证当前账号身份与两端元信息。
3. 明确选择保留方向：
   - **保留本地**：将本机备份作为保留版本，云端有可能被覆盖并推进 revision。
   - **保留云端**：恢复服务器保存的版本，本机现有记录有可能被替换。
4. 操作完成后重新检查当前数据与云端 revision；正常同步应重新收敛。

不要在另一台仍在学习的设备上，同时执行未确认的双向覆盖。若遇到冲突或状态不确定，优先保留备份而非强行继续。

## 6. 数据安全和已知限制

- 账号、密码与会话用于访问控制；云端读写经过 HTTPS。
- **云备份没有启用客户端端到端加密**。具备存储管理权限的一方理论上可以读取学习数据。
- 目前不保证多个设备发生分叉后自动逐词合并。
- 删除云账号是重大操作；应先导出并校验需要保留的完整备份。删除后，其他设备可能仍持有旧的本地副本，不能把这些副本视为已安全同步的云端数据。
- 当前 Beta 主要面向桌面 Chrome / Edge，云服务可用性和 EdgeOne 最终一致性仍需要持续验证。
