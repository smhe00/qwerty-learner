# Qwerty Plus Learn Alpha 1 客户使用说明

> 版本：`0.2.0-alpha.1`  
> 阶段：受控 Alpha  
> 正式域名：尚未公布；Alpha 访问入口由测试方单独提供。

感谢参与 Qwerty Plus Learn Alpha 的阶段性试用。

这一版本的重点不是增加更多“背单词按钮”，而是验证一种新的长期学习流程：

> 在不过度增加挫败感的前提下，用尽可能少的有效学习时间，让更多单词真正形成长期、独立的回忆能力。

Alpha 阶段仍会持续迭代。当前版本已经完成核心流程、数据安全边界和控制稳定性验证，但长期学习效率与个体化参数仍需要真实用户数据继续校准。

## 1. 建议使用环境

当前 Alpha 的核心学习流程以桌面浏览器为主要验证环境。

建议：

- 桌面 Chrome / Edge；
- 稳定网络；
- 学习前确认选中了正确词库；
- 重要学习数据建议定期做本地导出备份。

移动端当前主要是产品介绍页面，不是本次 Learn Alpha 的主要学习入口。

## 2. 两种模式

顶部可以切换：

```text
Typing | Learn
```

### Typing

Typing 保留上游项目的章节练习逻辑。

适合：

- 熟悉词汇；
- 打字训练；
- 章节练习；
- 发音、音标和释义辅助。

Typing 的表现不会直接把一个词判定为“长期掌握”。

### Learn

Learn 是长期学习模式。

新词大致经历：

```text
Exposure
  ↓
Supported Recall
  ↓
Independent Recall
  ↓
进入长期学习
```

到期后再进入长期 Review。

## 3. Learn 中“会写”与“掌握”不是一回事

第一次接触新词时，系统可能显示：

- 单词；
- 音标；
- 中文释义；
- 双语例句；
- 自动发音。

这一阶段主要用于建立理解和第一次成功体验。

真正形成“独立掌握”证据时：

- 单词拼写不会显示；
- 不依赖提示；
- 不能有拼写错误；
- 需要满足一定的间隔条件。

因此：

```text
看着答案写对
≠
已经长期掌握
```

## 4. 如果不会怎么办

在 Learn 的拼写过程中可以按：

```text
Esc
```

逐步获得 Hint。

系统会记录这次使用了帮助，所以提示后完成不会被误记成一次完全独立的回忆。

短语中的空格仍然是正常拼写字符，不是跳过键。

当一个词已经正确完成后，Space 可以用于快速进入下一个词。

## 5. 为什么有时系统会先安排几个比较容易成功的词

当最近连续出现明显困难，而且一个 Independent Recall 刚刚失败时，
系统可能暂时安排 2～3 个当前队列里更容易成功的训练项，再回到困难词。

这是 Recovery Window。

它的目的不是“放水”，而是避免连续失败造成学习节奏失控。

Recovery 中的成功：

- 不会直接算成新的长期掌握；
- 不会降低 Independent Recall 的标准；
- 不会无限连续触发。

## 6. 系统会自动调节什么

当前版本会根据近期真实学习经历自动改变：

- 新词数量；
- 当前词的支架强度；
- 是否启动 Recovery Window；
- 长期 Review 的调度。

系统观察的是可测行为，例如：

- 错误次数；
- Hint 深度；
- 纠错过程；
- 首键等待；
- Independent Recall 结果；
- 长期 Review 结果。

系统不会在界面上给学生贴“焦虑”“能力差”等心理标签。

当前 Alpha 的控制参数仍然使用经过约束的全局参数，**还没有启用自动 Personal Calibration**。

## 7. 为什么有时当天新词会变少

Learn 会优先保证已经到期的长期 Review。

原则：

```text
有 Due Review
→ 先复习

没有 Due Review
→ 再根据当天状态加入新词
```

当前新词上限会在 5 / 10 / 20 等档位中受控变化，同时还受当天学习时间预算影响。

这不是惩罚，而是避免“新词不断增加、旧词复习债务越来越大”。

## 8. 默认词库

当前默认词库：

```text
沪教新初2027
```

包含 1751 个词条，面向沪教版新初中英语词汇场景。

系统也保留其他原有词库，可以在词库选择中切换。

## 9. 手工移出不需要继续学的词

如果某个词对你明显没有继续学习价值，可以在 Learn 中使用：

```text
⋯
→ 移出学习计划
```

系统会保留历史记录，但不再安排该词。

之后可以恢复学习，历史不会因为移出而被删除。

## 10. 数据保存在什么地方

Qwerty Plus 采用 local-first 方式。

默认：

```text
浏览器本地 IndexedDB
= 日常学习的工作数据库
```

不登录也可以正常学习。

建议 Alpha 用户定期使用本地数据导出功能保存备份。

## 11. 云账号与同步

云同步是可选功能。

当前特性：

- 用户名 + 密码；
- 一个账号只保留一个当前有效云会话；
- 手工上传 / 下载；
- revision 冲突保护；
- 不自动合并两个设备上发生分叉的数据；
- 云端保存最近若干完整快照。

如果两台设备产生不同进度，系统会要求明确选择本地或云端版本，而不是静默覆盖。

### 数据安全说明

当前云快照通过 HTTPS 传输，并有账号/session 权限控制。

但是：

> 当前云快照不是端到端加密（E2EE）。

具备云存储管理权限的一方，理论上可以读取并解压学习数据。

如果你不希望使用云同步，可以只使用本地学习与本地备份。

详细说明见：

`docs/CLOUD_SYNC_USER_GUIDE.md`

## 12. Alpha 阶段我们最希望获得什么反馈

普通“好不好用”的反馈有价值，但以下信息更重要：

1. 某个词是否出现“明明不会却被认为掌握”；
2. 是否出现长期卡住、无法推进；
3. 是否出现连续提示过多、感觉系统太保守；
4. 是否出现连续失败过多、感觉系统太激进；
5. Learn 是否明显打断正常学习节奏；
6. 同一个词几天后是否真的还记得；
7. 云同步是否出现数据丢失、覆盖错误或状态不一致；
8. 页面刷新、切换词库、重新进入 Learn 后是否恢复正确状态。

如果反馈学习效果，最好同时说明：

- 使用的词库；
- 大致学习时长；
- 学了几天；
- 是“当场会写”还是“隔天/隔周仍会写”。

## 13. Alpha 阶段尚未承诺的能力

当前版本尚未承诺：

- 对每个学生自动学习出完全不同的一套控制阈值；
- 对所有人都已经达到数学意义上的最优学习效率；
- 完整 FSRS-6 主调度；
- 自动跨设备 record-level merge；
- 云端端到端加密；
- 移动端完整 Learn 体验。

这些能力会在真实数据与稳定性边界充分验证后逐步推进。

## 14. 当前算法的基本安全原则

无论系统如何调整帮助强度，都必须保持：

```text
有帮助的成功
≠
独立掌握

训练稳定
≠
降低长期记忆标准
```

我们的最终目标仍然是：

> 用尽可能少的有效学习时间，获得尽可能多的长期、独立、可迁移的记忆效果。

Alpha 阶段的真实使用数据将用于判断哪些策略真正提高这个目标，而不是只提高当场正确率。
