# QWERTY Plus: WordRecord retention and Backup V4 size (2026-10-13)

## Decision and rollout

- **P0 implemented in product/main**: all NEW ordinary Typing rows are compacted **at the write boundary**. Preserve ID generated by Dexie, dictionary, word, chapter, timestamp, per-word `timing`, `mistakes`, `wrongCount`, `sourceMode`, and telemetry attempt outcomes/latency/wrong positions; omit redundant per-key intervals and Learn-only research snapshots. Current Typing runtime still computes its classification from the full transient telemetry, so the live typing UI remains unchanged.
- **P0 implemented**: Settings > Data > “分析备份容量（只读）”. Generate an audited V4 snapshot, measure actual JSON/gzip/Base64 bytes per snapshot and independent table gzip sizes, and simulate historical Typing compaction (>90d) on an in-memory copy. Never persist its projection. Full V4 baseline fingerprint and source/export audit remain unchanged.
- **P1 pending a safe migration gate**: compact already stored Typing rows only via explicit, backup-first, S1 writer-lease/transactional user action, after comparative statistics, orthography profiles, V4 multi-device restore, account isolation, and sync revision gates. No automatic destructive migration. The preview is **not** evidence of an achieved space saving.
- **P2 not enabled**: Learn history compaction requires event-sourced FSRS replay and achievement/evidence parity. Existing `applyReviewOutcome` rebuilds from `wordRecords`; never delete/shorten Learn rating rows without a verified checkpoint and full restore/replay contract. Current scheduler remains unchanged.
- **P3 possible optimization**: incremental cloud sync and binary transport after production Blob 1MB+ writes and restore integrity are independently verified. Neither is part of this commit.

## Functional and safety contracts

1. `sourceMode !== typing`, records with `learnItemKind` or `reviewRatingDecision` are passed through unchanged. Existing/legacy rows are never rewritten by the new code.
2. Error Book, Typing history charts, and orthography profile retain `timing`, `wrongCount`, `mistakes`, attempt classification, latency and wrong positions.
3. Every Learn rating event, FSRS 6 D/S/due, acquisition/Block/DailySession, achievements, workspace identity and V4 complete-table restore remain bytewise unaffected by this P0 write optimization.
4. Synthetic 1–2.78MB **compressed** production stress payloads are random test material, not real learner backups. A 2.45MB **uncompressed incident diagnostic** is not a V4 gzip measurement.
5. Audit must distinguish whole-snapshot gzip from standalone table gzip, which are not additive. Base64 overhead is separately reported.

## Required gates before production

- New typing retention unit contracts and application Review Gate.
- Browser Typing lifecycle, Learn real journey, P4b browser recovery, S1 V4 workspace recovery; production EdgeOne big payload and restore gate remain open.
- No `master` release before the current V4 HTTP 500 capacity issue is resolved or explicitly accepted by release authority.
