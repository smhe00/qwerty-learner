先清文档错误、过期注释、重复状态入口和误导性测试命令；历史报告通过索引分类，不改写当时结果。已合并分支、演示资源和旧脚本只是候选，必须检查引用、开放 PR 与回退价值后才提出删除。

## 建议的稳定版收尾判据

1. 核心功能范围冻结；所有阻塞问题有责任人、复现和验收证据，而非只凭重跑变绿。
2. 受控恢复演练与目标真机矩阵完成，无记录丢失、重复计入或跨账号污染；失败不要求用户清库。
3. 静态检查基线、测试入口、发布/回退步骤和当前用户指南一致；每次发布保留精确 SHA。
4. 约定一个真实使用观察窗口，例如连续 7 天；统计未知同步失败和恢复结果，并对每一项形成解释或修复。此处是建议，不是已经启动监控或承诺后台执行。

本轮不推进 eTest/master、不读写用户账号、不清理云端数据、不删除分支、不更改功能或验证门槛。
