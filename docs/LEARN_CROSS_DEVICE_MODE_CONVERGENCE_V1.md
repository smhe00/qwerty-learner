# QWERTY Plus — 跨设备、跨学习方式数据融合协议 V1

> **状态：目标协议 / 设计基线（未实现，不是当前线上同步能力声明）**
>
> **范围：** 单手机、多手机、单电脑、多电脑、手机电脑混用，以及未来电脑使用轻触记忆模式、手机使用拼写重建模式。
>
> **开发分支：** \`product/main\`。没有经过所列 Gate 和实网验收，不得推断 \`master\` / \`etest\` 已具有这些能力。
>
> **命名：** 将现有界面中的“手机记忆模式”视为 **轻触记忆（Tap Recall）学习方式**，而非仅属于手机的学习系统。手机与电脑属于设备呈现层；Learn / Typing 属于产品任务边界；Tap Recall / Cold Spelling / Listening / Recognition 属于 Learn 内的练习交互方式。

## 1. 不可违反的设计决策

1. **一个账号 + 一个词库 + 一个单词 = 一份长期记忆模型。** 不为 \`phone\` 和 \`desktop\` 分别维护真实进度；设备、输入方式是证据字段，不是词库或账户的第二份身份。
2. **Learn 的单词历史事件是数据事实；FSRS-6 状态、今日完成数、能力画像、可见学习进度均为可重建投影。** 不以“最后一次上传的 reviewWordStates”压倒其他设备的事件。
3. **练习方式跨设备可用。** 桌面可选轻触记忆（鼠标点击、触屏、可选快捷键）；手机可选听音、点选、回忆，将来可选无键盘的字母重建。UI 能力不改变存储身份与调度合同。
4. **一次作答永不因同步被抹去或复制成多次。** 不可变 \`attemptId\` 去重，保留来源与时间，重复上传必须幂等。
5. **不同证据不等价。** 点选识别不能证明独立拼写；无提示、在答案揭晓前完成的心中回忆可以产生自评冷探测，但不得冒充客观拼写；电脑无提示拼写可作为较强的客观记忆与拼写证据。
6. **同一词并发复习不能无脑把两个 Good 都喂给 FSRS。** 每个维度的冷探测采用确定性仲裁和最小间隔门槛；其他事件保留为辅助证据。
7. **多设备不互相踢出、不要求全局写入锁。** 设备拥有自己的运行会话/本地草稿，云上汇合知识历史。Blob/KV 无原子 CAS、存在约一分钟最终一致性；不得把 revision 乐观锁当作原子一致性证明。
8. **账号工作区、匿名工作区严格隔离。** 未登录事件不得后台并入任意账号；跨账户转移必须显式确认，重放来源身份与新的归属动作可审计。
9. **不同词库互不影响。** 单词身份至少为 \`(accountId, dictId, wordKey)\`，词库 ID 必须稳定，不凭显示名称/释义自动把两本词库的同名词合并。
10. **失败闭锁于危险操作，不闭锁于学习。** 无网可继续本地学习；不能证明安全融合时停止云端覆盖与虚假的“已融合”提示，保留本机记录与导出能力。

## 2. 模式与设备是两条独立轴

| Learn 练习交互（\`exerciseKind\`） | 手机 | 电脑 | 核心证据 | 可改变 FSRS？ |
| --- | --- | --- | --- | --- |
| 初见展示 / 跟读（\`exposure\`） | 是 | 是 | 见过、听过 | 否 |
| 词义/拼写识别点选（\`recognition\`） | 是 | 是 | 有选项时识别正确 | 否；只能更新识别能力 |
| 听音辨词点选（\`audio-choice\`） | 是 | 是 | 听辨与选项识别 | 否；只能更新听力诊断 |
| 语境挖空点选（\`cloze-choice\`） | 是 | 是 | 带选项语境辨认 | 否；训练/诊断 |
| 无提示心中回忆、自评（\`tap-cold-recall\`） | 是 | 是 | 答案揭晓前的自我回忆评级 | **有条件**；仅有效冷探测 |
| 无提示独立拼写（\`cold-spelling\`） | 可选未来字母重建/外设 | 是 | 答案隐藏时实际拼写 | **有条件**；有效冷探测 |
| 错后提示、立即重练（\`assisted-practice\`） | 是 | 是 | 辅助巩固 | 否 |

\`inputMethod\`（\`touch/mouse/physical-keyboard/virtual-keyboard/letter-tiles\`）记录操作手段；\`deviceClass\`（\`phone/tablet/desktop\`）只记录运行环境。**无论在哪个设备，同一个 \`exerciseKind\` 应使用同一个评级合同**。

**注意：** Learn 与传统自由 Typing 仍维持原有产品边界。只有 \`sourceMode='learn'\` 且通过 Rating Gate 的冷探测才推进长期复习。普通 Typing 记录不能仅因打对字而隐式变成 FSRS Review 事件。

## 3. 学习维度与统一进度

### 3.1 主记忆轨（\`lexicalRecall\`）

- 每个账号、词库、单词只有一个**有效长期记忆 FSRS-6 投影**，与手机/电脑无关。
- 既可消化真实冷探测的 \`Again/Hard/Good/Easy\`，也必须拒绝所有 \`eligible=false\` 的训练/辅助行为；目标保持现有 FSRS-6 参数和可重放历史规则。
- 有效心中回忆的 \`Good\` 是**自评级**，不等同于“拼写已验证”；它可以作为带 \`evidenceMethod=self-report\` 的 FSRS 输入，**前提**是：答案、字母、发音未提前提示；答案揭晓前提交判断；必须是该单词该轮首次独立冷探测；无并发冷探测冲突；不允许将查看答案后选择 Good 伪装成答前承诺。
- 现有手机 P0 UI 在**查看答案后**才选择“忘了/模糊/记得”。这没有被可靠地证明为揭晓前的独立评级承诺，**不得直接升级为已验证冷探测**。迁移前必须先明确采集“揭晓前判断/承诺”的交互证据，或将相应积极评级视为诊断而非高置信度记忆成功。负向 \`Again\` 可触发保守补练。
- 电脑冷拼写成功的独立检索证据 \`evidenceMethod=objective-spelling\` 更强；仍遵循冷探测条件，错后补拼不能再递交第二次 FSRS。
- FSRS 本身是排程模型，不在事件上捏造一个“证据权重系数”传给 FSRS；证据强度由 Rating Gate 和掌握度/训练选择器解释。若未来要对自评成功限制长期间隔，须定义**可重放的版本化排程策略**，不能在某一端偷偷裁剪日期。

### 3.2 拼写能力轨（\`orthography\`）

- 独立保存最近一次客观无提示拼写成功时间、连续成功次数、常见错误类型和已验证标记。
- 手机点“记得”不填充“独立拼写正确”，不能解锁需要实际拼写的成就/熟练度。
- 现阶段可由 \`wordRecords\` 投影形成能力画像；**不要求立即增加第二个 FSRS 实例**。未来若给拼写能力独立间隔排程，应新增版本化维度状态而不是复制全局单词进度。

### 3.3 听力、识别和辅助训练轨

- 听辨选择题、意义识别、提示后练习均保存事实，供推荐下一种练习，但不把它们当作无提示回忆成功。
- 设备上的某种能力长期没有得到客观验证时，只应呈现“未验证”，不得暗示“失败”或重置已形成的记忆轨。
- 今日“完成词数”基于统一记忆目标与不重复的词身份；练习次数、触屏次数、拼写次数分别统计，不与每日新词数相加。

## 4. 原始事件合同（目标 Schema；当前 V4 不保证包含全部字段）

\`\`\`ts
type UnifiedLearningAttemptV1 = {
  schemaVersion: 1;
  accountId: string;             // 当前工作区归属，不从 deviceId 推断
  workspaceEpoch: string;        // 云账号重置/删除后必须变化
  dictId: string;
  wordKey: string;               // 词库内稳定身份
  attemptId: string;             // 不可变 UUID；跨设备去重键
  deviceId: string;
  clientSessionId: string;       // 本设备的运行会话，不是账号排他锁
  exerciseKind: string;
  inputMethod: string;
  deviceClass: string;
  knowledgeDimension: 'lexicalRecall' | 'orthography' | 'listening' | 'recognition';
  learningPhase: 'acquisition' | 'review' | 'reinforcement' | 'training';
  startedAtMs: number;
  submittedAtMs: number;
  clockQuality: 'calibrated' | 'local-unverified';
  baseKnowledgeFrontier?: string; // 开始作答时观察到的历史摘要
  cueTrace: unknown;             // 字母/释义/音频/例句/答案何时出现
  answerTrace: unknown;          // 本次选择/拼写、错数、答前承诺
  evidenceMethod: 'objective-spelling' | 'self-report' | 'recognition' | 'assisted';
  ratingGateVersion: string;
  ratingDecision: null | 'again' | 'hard' | 'good' | 'easy';
  ratingEligible: boolean;
  eventPayloadHash: string;      // 校验同 attemptId 的 payload 一致
};
\`\`\`

- 这是**待实施的规范层字段**，不等于当前 Dexie 数据表已具备这些列。可先在当前 \`IWordRecord\` 上加向后兼容的证据元数据，通过确定性适配器输出目标事件。
- \`id\`（Dexie 数字主键）只在本地有意义，合并不比较 \`id\`；同一 \`attemptId\`、不同内容 hash 为硬冲突，进入隔离区而非覆盖。
- 现有未具备 \`attemptId\` 的老记录需要经过**经验证的同源历史锚定**后才能合并；不得仅凭“同一个词、同一秒、同一数字 ID”推断它们是同一学习行为。
- 每个事件的评级由当时确定的策略版本和输入证据计算，融合时可重放且可审计。**禁止事后把原始 \`eligible=false\` 事件改成 \`eligible=true\` 而无策略迁移记录。**

## 5. 本地与云融合算法（目标语义）

### 5.1 三层数据的权限

| 层 | 真相来源 | 合并方式 | 跨设备同步后处理 |
| --- | --- | --- | --- |
| L0 原始不可变作答/排除/删除事件 | 每个设备追加的唯一事件 | 按 \`attemptId\` 联集、hash 核验、确定性排序 | 永久保留或按安全的 epoch/tombstone 策略整理 |
| L1 知识模型与能力画像 | L0 重放投影 | **不比较最后写入时间，不按表覆盖** | 按 \`(dictId,wordKey)\` 重算 FSRS / 能力维度 / 成就事件 |
| L2 运行会话、队列光标、按钮状态 | 各设备自己的短期会话 | **不做字段级光标合并** | 继续本设备会话前对照最新 L1 重新校验下一任务 |

全局“今天已学多少词、今天还需复习什么”来自 L1 + 稳定日目标；设备上的 \`reviewRecords.index\`、暂停状态、当前卡片草稿属于 L2，不能让电脑的 index 覆盖手机的 index。

### 5.2 幂等、交换顺序和完成条件

1. 每个设备离线也能原子保存本机事件，标记 \`pending-upload\`，立即可继续学习。
2. 云写入采用按 **accountEpoch/deviceId/attemptId**（或等价唯一位置）分别写入的事件 Blob；不要写一个全局活动 JSON 后假设 CAS。逻辑不可变事件重试时字节完全一致，SHA 验证。
3. 网络恢复时先上传并确认本机缺失事件，再获取尽可能完整的其他设备事件。由于 Blob 最终一致性，**写入回执或一次 list 查询不等于全账号已收敛**；以读回校验 + 全部已知设备 frontier 覆盖等证据给出确认状态。
4. 事件集求并集满足交换律、结合律、幂等律：\`merge(A,B)=merge(B,A)\`；\`merge(merge(A,B),C)=merge(A,merge(B,C))\`；\`merge(A,A)=A\`。
5. 根据已确认时钟和因果 frontier，按学习历史重放 FSRS-6；同 timestamp 排序要按跨设备稳定 ID，而不是本地数字行号。发现时钟不可靠/同事件 ID 内容不同则**禁止写入派生云快照**，保留本机事件并提示待核验。
6. 增量索引、压缩分块及 checkpoint 只为性能，不具事实权威。checkpoint 丢失后应可从事件重建。V4 全量备份仍提供保底导出和灾备，不在验证不足时用“最新快照覆盖整库”取代事件并集。
7. 登录工作区隔离、事件 epoch、云重置和账户删除必须配套**防复活规则**：旧设备/旧 token 不能在重置后重新上传过期 epoch 的历史。
8. 多端实时视图允许短期落后，**不允许悄悄丢弃已确认的独立历史**。设备断线时标注“本机已保存 / 待同步”；所有事件已上传但尚未核对完整时标注“已上传 / 待融合”，完成证明后才标注“已融合”。

### 5.3 同一单词同时被两个设备学习（重点）

- 不做“这个词只能被一台设备回答”的原子租约。两个设备可分别完成，事件均保留。
- 若两设备在相同 \`baseKnowledgeFrontier\` 下并发完成一个词的同一维度冷探测、且时间不足以构成真正间隔复习，则形成**一个冷探测竞争组**：**最多一次**评级进入 FSRS，其他尝试是训练/诊断证据。
- 竞争组的评级采用安全的确定性策略：优先保留更强的真实客观证据，但**负向独立失败不能被另一设备的 Good 隐藏**。发生矛盾时保守处理，最多按最弱可信结果推进，并将异常记录为需复核。不得因为服务器事件先到或客户端 UUID 大小决定记忆掌握。
- \`baseKnowledgeFrontier\`、校准的作答时间、最小间隔和评级仲裁都必须经过算法规范版本化和模拟验证；证据缺失时不自动提升长期间隔。
- 如果两个独立有效复习有可证明的时间顺序且满足冷探测间隔，按顺序重放，两者均可计入（例如早上电脑、晚上手机）；不能把一天内对同一个词的所有事件粗暴去重。

## 6. 每日目标 / 会话接力

1. 账户词库的一天由一个**明确设置的学习时区**（IANA 时区 ID，例如 \`Asia/Shanghai\`）界定，而非每台机器当前位置的自动时区。跨境使用不导致重复“新的一天”。
2. \`dailyNewTarget\` 和当日去重的首次引入词名单是共享逻辑事实；同一词在两端首次学习只计一次。
3. **不同设备拥有独立运行会话。** 电脑剩下 4 词、手机停在第 7 词，不互相覆盖光标；刷新本设备继续最后一个未完成卡片。
4. 每次开会话、完成 Block、主动同步/恢复后，依据共享知识快照审查尚未作答的词：已完成/不再到期的跳过，真正仍到期的保留，未完成的 acquisition 不能当作 mastered。
5. 不能保证离线两端分别选取不同新词；重叠时按首个合法引入事件去重，其他事件保留为训练/巩固，不重复消耗每日名额。已到手但尚未上传的离线数据仍标记“等待收敛”。
6. 全局完成率来自事件集合的确定性投影；本机进度条仍可以标记“当前设备会话”而非假装实时全局已完成。
7. 同一设备在轻触记忆与独立拼写之间切换时：**共享词库、原始事件及复习调度，但不共享同一个 UI 控件状态**；当前未提交的答案丢弃，已提交的记录保留。任务模式变更不构成账户切换或重置。

## 7. 使用场景与确定行为

| 场景 | 期望行为 | 不允许发生 |
| --- | --- | --- |
| 单手机，仅轻触记忆 | 本机 Learn 历史、FSRS、今日计划连续 | “没有电脑就无法毕业”或凭选择题冒充拼写掌握 |
| 多手机，同一账号 | 每手机独立会话，账号知识合流 | 某手机上传覆盖另一手机记录 |
| 单电脑，拼写 + 轻触记忆 | 模式切换仅改变出题/输入，使用同一词库/FSRS | 切换模式重置今日新词额度 |
| 多电脑，同一账号 | 独立会话；历史汇合后重算到期 | 最近上传者决定所有人的进度 |
| 手机 + 电脑交替在线 | 手机已复习词在电脑刷新后不再错误到期；电脑拼写证据在手机可见 | 用手机识别题的 Good 冒充电脑正确拼写 |
| 手机 + 电脑同时在线，同词 | 各保存一次，竞争组至多一个 FSRS 冷探测 | 两个 Good 意外把间隔翻倍 |
| 手机 + 电脑离线分别学习后联网 | 先保留两边本地事件；重连后汇合与可重建 | 全库覆盖/最后写入获胜 |
| 不同时区手机 + PC | 按账号学习时区合计单日额度 | 在东京/上海之间产生两份今日目标 |
| 使用不同词库的两设备 | 按不同 dictId 独立计数、调度 | 同名词跨库混算 |
| 同设备多个浏览器 Tab | 共用工作区安全门与本机事务约束；可读状态协调 | 双 Tab 同时改写同一活动会话光标 |
| 同账号注销并换账号/匿名 | 工作区硬隔离、保留归属；重新验证身份 | 旧账户事件进入新账户 |
| 云 reset/删除后旧设备联网 | 新 epoch / 撤销令牌拒绝旧历史复活 | 旧设备上传把已删数据恢复 |
| Pages 测试端 + 正式站 | Pages 仍禁云，数据独立；测试不能污染生产 | 以同屏外观暗示进度自动同步 |

## 8. 实施阶段与上线门禁

### P0 — 同设备手机/电脑记忆一致性（先做）

- 将“保存原始作答 → Rating Gate → 有效 FSRS 更新 → 会话推进”的事务与回放入口收敛为同一个 Learn 协调器，两个 UI 不能各自实现不等价的提交路径。
- 修复已核实的手机现状：\`MobileWordPractice\` 写 \`wordRecords\` 但没有像桌面 \`Word\` 一样调用 \`applyReviewOutcome\`，已有 \`reviewWordStates\` 可能留在旧排期。
- 明确手机 **答前承诺**、揭晓动作和正向自评资格；不能把揭晓后 Good 当作已验证无提示冷探测。
- 旧记录保持可读取：按 provenance 与策略版本重放；没有充分证据时只允许保守巩固，不可编造已掌握。
- **Gate：** 同一浏览器先桌面复习后轻触记忆再桌面，前后 FSRS、同词历史、每日目标、成就引用一致；三档按钮不制造双写。

### P1 — 同设备任意方式切换（电脑加入轻触模式）

- 将 \`/mobile/study\` 从“学习算法模式”降级为呈现入口；PC Learn 可直接选“轻触记忆”/“独立拼写”，所有入口进入相同 Learn 会话控制器。
- 学习方式偏好可以按设备记住，但不能覆盖账号全局的记忆模型。手机登录可选适合手指的任务，电脑可选鼠标点选。
- **Gate：** 电脑/手机/平板同一种练习相同原始证据、评级逻辑；切换方式不删除当前有效排期。

### P2 — 只读事件汇合与重建

- 在既有 \`src/sync/v4-merge-preflight.ts\`、\`v4-event-convergence.ts\` 上发展完整覆盖的只读投影，验证 UUID、旧数据锚定、时钟、同词并发、排除状态、成就、会话重建。
- 验证新/旧 V4 导入后所有六张表与学习时区元数据的一致性，不只比较 FSRS \`reviewCount\`。
- **Gate：** 属性测试 \`commutative/associative/idempotent\`，不同设备/离线/冲突/乱序/重复上传/断电恢复，可重复重建 SHA 完全一致。

### P3 — EdgeOne Blob 事件合流与安全接力

- 采用按设备/作答独立 Blob + 校验 + 可恢复 checkpoint 的事件模型，不依赖 KV/Blob 原子写。
- 同步状态可观察；必须有故障注入、真实云延迟和账号撤销测试。
- **Gate：** 三设备（手机 2、电脑 1）+ 双账号 + 匿名环境覆盖；同词冲突及异词合流均无丢失，断网/并发事件最终收敛；生产前在 \`etest\` 独立 Blob 空间核验。

### P4 — 更丰富能力任务（可在 P3 后渐进）

- 手机加入字母拼写重建、电脑加入听辨/轻触交互；可按薄弱维度自适应挑题。
- 成就系统区分“持续学习”“记忆检索”和“独立拼写熟练”，不因换设备发生刷成就或失去资格。

**发布原则：** P0、P1 可独立在 \`product/main\` / Pages 验证；跨设备自动融合不能借用当前保守 V4 全快照同步“先上线再补证明”。不得在 Merge Gate 通过前把 P2 只读投影宣称为正式可写合并能力。

## 10. 形式化性质与测试断言

1. **NoLoss:** 对任意已持久化且未被合法删除的 \`attemptId\`，最终合流后的事件集都包含它。
2. **NoDuplicate:** 同一 \`attemptId\` 只计一次；重复传输不会增加 \`reviewCount\`、每日新词数或成就事件。
3. **NoFalseSchedulerEvent:** 任意 \`eligible=false\` 或同一竞争组的次级尝试都不会改变主记忆轨 FSRS 计数。
4. **DeviceIndependence:** 重放相同事件集合时，任意事件归属手机/电脑的变化都不会改变知识模型（证据本身不变）。
5. **OrderIndependence:** 下载顺序、Blob list 顺序、重试次数与最终派生 SHA 无关。
6. **SessionIsolation:** 设备 A 的 L2 光标变化不会直接改写设备 B 的当前未提交操作。
7. **WorkspaceIsolation:** 账号/匿名/epoch 不同的事件不会静默跨界。
8. **CrashRecovery:** 任意步骤失败后可从本机事务日志和云上可验证事件恢复，不能出现“显示已同步但丢了历史”。
9. **ConservativeConflict:** 无法判定的双端并发/时间漂移不能增加长期正向调度，也不能阻止用户离线记录。
10. **CrossModeProvenance:** 自评成功不满足“独立拼写成功”；同一词的能力标签按事实而非设备名计算。

**本文是目标语义与验收基准，不是对现有云端已完成 M2/M3/M4 能力的声明。** 实施需另起变更、逐步通过 Gate、保留旧 V4 可靠导出路径。
