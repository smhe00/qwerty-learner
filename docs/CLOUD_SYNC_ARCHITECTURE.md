## 1. 三种版本不要混淆

| 名称 | 含义 |
| --- | --- |
| `0.2.0-beta.1` | 产品 package 版本；精确运行版本还需源代码 SHA。 |
| `qwerty-backup-v4` | 完整备份格式。 |
| S1 / S2 / M3 / M4、`/api/sync/v2`、持久化 key 的 `.v1` | 工程层、API 或存储协议名称；不是看到旧数字就可删除的废弃功能。 |

旧架构所述“当前 V3 + Base64、Pages 共享生产云后端、V2 尚未实现”不再适用。

## 2. 部署与身份

`product/main` 是开发集成线；Pages 禁用云能力。`edgeone-test` 对应 `https://t.smhe.cn` 的独立测试云存储；`master` 对应 `https://q.smhe.cn`。默认 EdgeOne 域名是历史/兼容入口，不代替正式地址。

客户端学习事件的准入源见 [learning-sync-policy.ts](../src/sync/learning-sync-policy.ts)。S2 完整快照还受相应部署配置控制；不能仅凭页面路由存在推断云功能已经启用。

保留单账号单有效会话。匿名与账号工作区隔离；已有账号登录不自动吸收匿名数据。认证、工作区归属和单标签页写者权限是三种不同约束，不能互相替代。

## 3. 本地安全与完整备份

S1 在应用写者挂载前获取独占写权限并处理待恢复事务。完整 V4 备份覆盖六表、每日会话、设置和导航。恢复/切换必须先验证目标与身份，再经持久日志、恢复、读回校验和最终完成等受保护步骤。

主要实现入口为 `src/sync/workspace-*`、`workspace-v4*`、`manual-backup-v4.ts` 与 M4 事务模块。历史版本围栏、崩溃恢复日志、Typeson/Unicode 校验及类映射是安全边界，不属于可以按文件名批量清除的“旧代码”。

## 4. 完整 V4 与学习事件是两条互补路径

**完整历史协调：** 登录/启动持有 S1 写者权限时，经 [account-login-v4-check.ts](../src/sync/account-login-v4-check.ts) 调用受保护执行器。它负责完整快照的 no-op、上传、拉取和受支持分叉自动协调。离线、失败或不支持的证据保留为 pending；不能把认证成功解释为完整历史已经恢复。

**学习事件持续传递：** [m3-publication-browser.ts](../src/sync/m3-publication-browser.ts) 恢复并发送当前账号的持久 outbox；[m3-background-browser.ts](../src/sync/m3-background-browser.ts) 处理适用后台检查和空闲恢复入口。M3 收据不授权直接覆盖完整 V4，也不能证明所有设备头或所有六表已收敛。

M4 在受保护的新事务上下文中恢复合并候选。不能在仍有挂载写者时直接改写 Dexie；也不能把不完整 Blob 列举当作完整设备发现。

部分函数仍带 `etest`/`pilot` 历史名称。M3 publisher 已显式复用 approved-origin policy，背景模块注释仍有旧称；应整理注释与命名，但不能仅按名字认定代码只在测试站运行或可以删除。

## 5. 自动六表合并的实际边界

[automatic-v4-browser.ts](../src/sync/automatic-v4-browser.ts) 要求双方是同一不可变账号、表清单与 schema 受支持、未知运行字段不冲突。它在隔离临时库解码双方，使用一致类映射，构造候选并再次独立导入校验 raw IndexedDB 值；不是直接改写工作库后再碰碰运气。

合并包含引用重映射与六表核验。当前策略还明确：设置键冲突时使用远端值覆盖对应本地键；导航采用远端选择；每日计划按实现的确定性规则选择代表状态并重映射完成阶段引用。**“学习事实保全”不等于所有 UI 状态求和，也不等于任意未知 schema 都可合并。** 详细记录合并由 `automatic-v4-records.ts` 实现，后续修改必须有对应契约测试。

完整压缩备份使用二进制上传/下载路径；直传与分片适配不应重新描述为旧 V3 Base64 主链路。传输 SHA、逻辑指纹、云 revision、完整数据读回分别提供不同证据，不能只验证记录条数就认定无损。

## 6. 失败与重试

HTTP 500/超时可能发生在写入前或写入后。未知结果不得直接推进成功基线，不得盲目重放破坏性操作。数据与候选/回退证据应保留，下一次依据可验证远端状态处理。

本地 IndexedDB CAS、模拟服务端 CAS 和真实 Blob 并发能力不是同一回事。不得以 mock gate 通过推断存储平台提供未验证的原子写入；平台保证须另行核验，正式验收保留 eTest 实网证据。

## 7. 自动同步与 UI

[CloudSyncSetting.tsx](../src/sync/CloudSyncSetting.tsx) 明确区分只读状态、立即同步和高级恢复。每日全部完成仍可自动同步，每 Block 同步开关默认关闭且仅本机当前账号生效。正常受支持分叉自动协调；高级替换恢复是异常处理，不是普通分叉的默认交互。

手动文件导入始终是明确替换，不是自动合并，也不是直接覆盖云端的授权。

## 8. 运维与验收边界

云备份不提供客户端 E2EE。日志、测试产物不得含密码、令牌或完整个人备份。日常排障先保留数据、导出备份、区分认证/传输/校验/提交阶段，不以清库恢复可用性。

最近发布证明和首轮失败见 [发布报告](../interactive/reports/MOBILE-MENU-RELEASE-20261025-report.md)。注册偶发失败、revision 观察异常、测试身份清理、全仓静态检查和真机覆盖仍见 [收尾清单](./release/BETA_CLOSEOUT_2026-10-25.md)。历史运维/部署文档中的配置默认值和平台能力不能未经当前源码或实网核对直接执行。

圈子是独立实验 API 范围；API 存在不代表用户前端、账号删除与数据生命周期已完整验收。见 [圈子 API 边界](./CIRCLE_PUBLIC_API_LAUNCH_20261017.md)。
