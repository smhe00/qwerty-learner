# 错题复习与间隔复习使用指南

> **Product migration note:** The top-level product mode is now **Learn**, not
> Review. This document describes the legacy/error-word Review behavior that
> remains as an internal Learn subsystem during Phase A/B. For current user
> navigation and exclusion/restore semantics, see `LEARN_USER_GUIDE_V1.md`.
>
> 本文面向使用者，说明当前功能“怎么用、会发生什么”。  
> 算法、数据库和代码结构请看 `REVIEW_SYSTEM_ARCHITECTURE.md`。

## 1. 当前功能是什么

当前的 Review 是“**按词库管理的智能错题复习**”。

它不是全局错词本，也不是“所有学过的单词都自动进入复习”。

当前进入复习队列的条件是：

```text
当前词库的历史错词
        ∩
当前已经到期的词
        ↓
本次错题复习
```

因此，同一个单词如果同时存在于两个词库中，会作为两个独立的复习对象管理。

例如：

```text
cet4 / receive
middle-school / receive
```

二者的复习状态互不合并。

---

## 2. 如何开始错题复习

进入某个词库后：

```text
词典
→ 错题回顾
→ 开始复习
```

如果当前没有到期的历史错词，会提示：

```text
当前没有到期需要复习的错词
```

这不表示历史错词被删除，只表示它们还没有到下一次复习时间。

如果上一次 Review 尚未完成，可以继续当前进度。

---

## 3. 什么词会进入 Review

当前版本只复习“曾经出错过”的词。

也就是：

```text
历史上至少错过一次
+
当前已到期
=
可以进入错题复习
```

第一次学习时从未出错的词，即使系统已经记录了它的学习行为，目前也**不会因为 clean 就自动进入错题回顾**。

后续如果增加完整的 spaced-learning / all-learned 模式，应作为独立候选策略实现，不改变当前错题复习语义。

---

## 4. 复习时间如何安排

当前基础间隔为：

```text
1 天 → 3 天 → 7 天 → 14 天 → 30 天
```

系统根据实际输入表现决定本次结果大致属于：

- `again`：明显需要重新学习；
- `hard`：完成了，但证据较弱；
- `good`：表现正常；
- `easy`：接口已预留，当前输入分类暂不主动产生。

基本规则：

- 真正到期后表现良好，间隔逐步延长；
- 明显遗忘会回到较短间隔；
- 同一学习会话中的立即重复，不会反复把长期间隔往后推；
- 提前练习成功，一般不会把原来的到期日继续推迟。

---

## 5. 为什么错词会在几词后再次出现

Review 中如果一个词出现错误，不会只要求用户当场重新敲对一次就结束。

系统会把它重新插入当前队列，通常在若干个其他词之后再次出现。

当前大致策略：

| 错误类型 | 大致再次出现间隔 |
|---|---:|
| 回忆困难 recall | 3 个词后 |
| 稳定拼写错误 spelling | 4 个词后 |
| 无法可靠判断 uncertain | 5 个词后 |
| 更像手滑 motor | 7 个词后 |

如果已经有一个相同单词等待再次出现，不会无限重复插入。

这一机制只用于 Review 会话；正常词库章节学习目前仍保持原项目流程。

---

## 6. 系统会记录哪些学习行为

为了判断一次输入到底有多强的学习证据，当前会额外记录两类可选信息。

### 6.1 输入行为

包括：

- 第一次按键前等待时间；
- 每次尝试从准备到首键的时间；
- 输入总耗时；
- 错误位置；
- 错误按键；
- 连续按键间隔；
- 一次单词中经历了多少次错误尝试。

这些数据用于区分：

```text
真的想不起来
稳定拼错
手滑打错
无法可靠判断
```

### 6.2 当时的学习条件

还会记录：

- 英文答案开始时是全显示、部分显示还是隐藏；
- 英文字母实际可见比例；
- 是否主动显示过答案；
- 是否在第一键前看过答案；
- 看答案到第一键之间隔了多久；
- 中文释义开始时是否可见；
- 是否后来显示过释义；
- 音标是否可见；
- 是否播放过读音；
- 读音发生在第一键前还是后；
- 是自动播放还是用户主动播放。

这些信息的目的，是区分：

```text
照着答案打对
```

和：

```text
在没有看到答案时独立回忆并打对
```

当前版本已经保存这些条件，但**除“注意力不确定”保护外，尚未用这些条件直接计算长期掌握度权重**。后续应通过真实复习结果校准后再使用。

---

## 7. 用户走神或切到别的窗口怎么办

系统不会简单把“很久没打字”解释成“不会”。

### 切后台 / 失去焦点

例如：

```text
看到单词
→ 切到别的软件 30 秒
→ 回来继续输入
```

这 30 秒不会计入有效首键延迟和有效输入时间。

同时系统会保留后台暂停次数和暂停时长，便于后续分析。

### 页面一直在前台但长时间没有操作

如果页面一直处于前台，但出现非常长的无解释停顿，当前会标记：

```text
attentionUncertain
```

含义只是：

> 这次观察不够可靠。

它不等于“确定走神”，也不等于“确定不会”。

当前阈值是 15 秒，属于保守启发式规则，后续应根据真实数据校准。

---

## 8. 原有数据是否兼容

兼容原版 Qwerty Learner 的历史数据。

原版数据没有：

- `typingTelemetry`
- `learningContext`
- `reviewWordStates`

都属于正常情况。

规则是：

```text
字段不存在
=
不知道 / 旧数据
```

而不是：

```text
字段不存在
=
用户没有发生对应行为
```

旧历史错词第一次迁移到新的复习状态时，会按“现在需要复习”处理，而不是根据过去普通练习记录猜测一个未来日期。

旧历史中的 clean 普通练习不会被当作间隔复习确认，从而避免把历史错词错误推到很久以后。

---

## 9. 备份与导入

原项目的数据导出/导入仍然可用。

新版本会额外保存派生的 Review 状态。

如果导入的是旧版备份，其中没有 Review 状态，系统会清除本地旧的派生状态，并根据导入后的 `WordRecord` 在需要时重新建立。

原始历史记录仍然是主要事实来源。

---

## 10. 当前版本明确没有做什么

当前还没有：

- 全局跨词库合并同一个单词；
- all-learned / 所有已学单词自动复习；
- 完整 FSRS 调度；
- 根据“英文显示比例、释义、发音”等条件直接学习一个最终掌握概率；
- 自动训练个人化模型；
- 修改原项目的主学习 UI。

这些可以以后逐步加入，但不应该和当前错题复习混成一个不可拆分的大功能。

---

## 11. 本地开发版诊断

开发模式可以在浏览器 Console 中查看：

```js
await window.__qwertyReviewDebug.inspect('词典ID', '单词')
await window.__qwertyReviewDebug.due('词典ID')
await window.__qwertyReviewDebug.stats('词典ID')
```

其中可以看到：

- 当前到期状态；
- 下一次复习时间；
- 历史错误统计；
- 最新输入 telemetry；
- learning context；
- classifier 结果；
- attention-uncertain；
- Review 调度状态。

这是开发诊断功能，生产环境不会安装该全局调试接口。
