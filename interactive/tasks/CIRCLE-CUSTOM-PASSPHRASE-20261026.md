# Owner-defined Circle passphrases
Status: REVIEW. Application SHA 951f88ba2a9f6b6db81b45523b4ee1e998d503ab is deployed and Circle-qualified on etest; no master release.

Support owner-set 2-32 Unicode-character passphrases, NFC/trimmed ends, case sensitive. Owner confirmed: passphrase-only join; normally occupied phrases must be rejected. Reject normally occupied phrases; concurrent collisions must fail closed rather than join an arbitrary circle. No CAS/lock, no anonymous lookup, preserve account/IP limits and 3/50 advisory limits. Store hashes server-side, retain current authentication/deletion holds. Legacy QC3 codes and old pending creations remain compatible until owner changes the invitation. Owner-only setting for existing circles, invalidates old invite for new joins but preserves members. Creation recovery keeps exact name, phrase and operation ID. UI supports create/join/change/copy, avoids stale local invitation display after rotation.

Validate Unicode/invalid input, occupancy/collision, owner-only change, wrong/old phrase, retry identity, legacy compatibility, HTTP receiver and browser flows. Build/scoped lint; push development and test on etest with isolated synthetic data. No changes to learning/sync data or production.
