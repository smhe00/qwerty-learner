# 用户可见界面 P0 核查

## 结论与范围

根据用户要求，对实际生产构建进行界面级检查，并修复发现的问题。此任务独立于 CURRENT_TASK 的 Circle 性能任务，不修改该任务状态；不推进 etest 或 master。

不能用“DOM 中存在按钮”证明用户看得见、点得到。本次检查包含真实绘制后的对比度、可访问名称、视口和滚动容器裁剪、遮挡后的点击命中、页面横向溢出、错误后可见的重试/退出、键盘焦点以及未捕获页面异常。

手机 320×568（浅色）/390×844（深色）、触控平板 1024×600（双主题）、桌面 1440×900（双主题）；另测手机横屏 844×390 与 200% 根字号。浏览器为本地 Chromium，所有账号、圈子和网络失败均使用合成数据/拦截，不操作真实客户账户。

## 根因与修复

| 问题 | 修复与约束 |
|---|---|
| 懒加载同步模块导入全局 CSS，导致 reset 后加载并覆盖按钮底色 | 仅文档入口 `src/index.tsx` 持有全局 CSS；移除 app 与同步功能模块的重复入口。独立宋韵预览保留自己的文档入口。静态检查源导入、单一 reset 产物、HTML head 引用及锁定 Tailwind 版本。 |
| 设置页粘性保存区遮住发音/语速/试听内容 | 页头、可滚动表单、保存区分开排布；保存按钮使用原表单的 form 属性；沿用 visualViewport 适应软键盘。保存、边界校验和设置语义不变。 |
| 隐藏备份文件输入被通用输入样式放大，产生横向溢出 | 使用原生 hidden，通用输入样式排除 file 类型；继续由可见按钮触发文件选择。 |
| 手机品牌/次要文字、登录说明、成就筛选、词库选中态、错词、圈子日期/危险操作等对比度不足 | 使用成对的主题前景/背景变量；移除降低正文可读性的透明度，调整特定低对比度颜色。 |
| 图标、开关、滑块缺少名称，部分操作仅绑定非按钮元素 | 为发音/翻页/字体音量等提供名称；单词切换、返回、删除、导出采用原生按钮；补齐 progressbar/group 语义及统计滚动区键盘入口。 |
| 暂停遮罩下的桌面控件仍可被定位/聚焦；开始依赖按键 | 暂停内容 inert + aria-hidden；提供明确“开始练习/继续练习”按钮。学习推进函数、计时与保存契约沿用原实现。 |
| 藏品与错词详情缺少完整模态焦点约束 | 使用项目现有 Headless UI Dialog；支持 Tab 留在弹窗、Escape/关闭、背景隔离。错词详情限制视口高度并可滚动；藏品保留 portal 后需要的图片变量与主题颜色。 |
| Typing 统计首帧将空数组传入 ActivityCalendar，生产包抛错后白屏 | 统计 hook 显式加载/失败/重试；热力图对空数据防御。只读计算和数据结构不变；测试注入读失败并验证重试恢复。 |
| 其他未来渲染异常缺少统一可见出口 | 新增渲染错误边界，显示“重新加载/返回首页”。不会清空数据、自动重写进度或声称保存成功；恢复重新经过原 guarded boot。生产 chunk 故障注入验证出口及检查点保留。 |
| pre-mount 备份/恢复页面使用固定浅色文字和背景 | 换为主题变量及一致的触控控件外观；不修改账户校验、恢复事务或写入逻辑。 |

## 自动工具不能直接判定的项目

axe 的 `incomplete` 保留在逐状态 JSON 中，不当作 PASS 删除。人工复核包括：Headless UI 的屏幕外焦点哨兵；暂停覆盖下的非当前内容；滚动后被裁剪的账号内容；宋韵伪元素/渐变背景；反馈与设置的局部重叠报告。最终 360 状态中保留 40 个状态的 aria-hidden-focus 待核查项、58 个状态的 color-contrast 待核查项；同一状态可含多个节点。无效 aria-label 的 group/progressbar/图标语义已经修复，已无该类 incomplete。宋韵截图必须等入场遮罩消失，不能把 760ms 入场动画截图当成静态低对比度证据。

已查看手机学习按钮、设置保存、双主题宋韵、藏品详情、深色结算与整页异常恢复等实际截图。审计报告里的自动规则通过不等于完整 WCAG 认证，也不等于所有状态或设备已经穷尽。
